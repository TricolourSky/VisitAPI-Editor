# VisitAPI Editor

> SPT 4.1.1 的可视化**剧本 + 任务**编辑器

**中文** · [English](README.md)

---

让**不写代码的人**也能给 SPT 商人写剧情和任务。

- **对话编辑** — 打开 `.dlg` 剧本，一边写台词一边看到它在游戏对话框里长什么样，
  顺手接背景图、视频、语音、BGM，右边实时画出整张分支流程图。配合 VisitAPI 商人对话框架使用。
- **任务编辑** — 做的是**标准 SPT 任务文件**，**不依赖 VisitAPI**。目标、奖励、失败分支、
  四封邮件、玩家台词全都能改；物品/地图/商人清单直接读游戏自带数据，不用背 24 位 id。

两边还连着：任务能挂到对话的某个选项上（玩家点哪句话才接到这个任务），点一下就跳过去。

### 它长什么样

一个本地网页应用：双击 exe → 自己起一个只监听 `127.0.0.1` 的小服务 → 自动打开浏览器。
没有安装程序，没有依赖，**一个 300 KB 的 exe 就是全部**。

```
侧脊 · 数据头 · 左视口 / 右流程 · 遥测条
```

**对话编辑**

- **实时预览** — 背景（PNG/JPG/MP4/WebM）+ 塔科夫原生版式的对话框，点选项就能走分支
- **流程图** — 自动分层布局，一眼看清 35 个节点怎么连；断链会标红
- **章节索引条** — 每条独立故事线一根刻度，点一下跳过去
- **分拍编辑** — 一个节点里的多段旁白各自独立，能配各自的背景和语音
- **音频** — BGM（节点级）与语音（每拍），选择时可直接试听
- **保注释保行序** — 保存不会把你写的注释和排版洗掉（见下方「回写保真」）

**任务编辑**

- **四个页签** — 任务卡（描述/目标/奖励/初始装备/接取条件）· 对话挂接 · 失败分支 · 属性
- **说人话** — 条件不再是 `CounterCreator`，而是「击杀 5 个野人（立交桥）」；
  奖励里的 `5449016a…` 直接显示成「卢布」
- **物品选择器** — 4288 件物品，中英名都能搜，数据来自 `SPT_Data\templates\handbook.json`
- **配图选择器** — 任务卡那张图，可以挑 SPT 自带的 332 张、挑你自己模组 `images\quest\icon` 下的，
  或者自己填路径
- **任务链图** — 按前置深度自动分层（LV.0 / LV.1 …）；**从卡片上拖一条线就是一条前置**，
  成环 / 自连 / 重复都会被拦住
- **对话挂接** — 看得见「玩家点哪个选项才接到 / 交掉这个任务」，两步就能挂上；点一下跳到对话编辑器
- **存哪由你定** — 不依赖 VisitAPI，任务可以存进任何一个 mod 的 `db` 目录（见「任务存到哪」）
- **校验** — 没目标、完成邮件空、前置任务不存在、id 重复、商人找不到…… 13 条规则

还有一页**程序介绍**（侧栏第一项，也是打开程序时的落地页）：每个模块能干什么、哪些还没做，
以及这台机器上实际认到的几个路径。

两边共用：深浅双主题、中英双语（界面语言和你写的文案语言分开）。

### 安装与使用

1. 从 [Releases](../../releases) 下载 `VisitAPI.Editor.exe`
2. **放进 EFT 根目录**（和 `EscapeFromTarkov.exe` 同级），双击
3. 浏览器自动打开；剧本从 `<EFT>\BepInEx\config\VisitAPI\` 里挑

放别的地方也行，第一次会让你指一下 `.dlg` 所在目录，之后记住。

**需要 .NET 10 桌面运行时 + ASP.NET Core 10。** 装了 SPT 就已经有了——
SPT 服务端自己的 `runtimeconfig.json` 就依赖这两个，所以这里不额外要求任何东西。

### 素材放哪

跟插件读的是同两个目录，所以编辑器里能选的，游戏里一定找得到：

| 类型 | 目录 | 格式 |
|---|---|---|
| 背景 | `<EFT>\BepInEx\config\VisitAPI\backgrounds\` | `.png` `.jpg` `.webp` `.gif` `.bmp` `.mp4` `.webm` |
| 音频 | `<EFT>\BepInEx\config\VisitAPI\audio\` | `.ogg` `.mp3` `.wav` |

### 任务存到哪

**任务编辑不需要装 VisitAPI**，写出来的就是标准 SPT 任务文件（`db\quests\*.json` + `db\locales\*.json`）。

但有一件事必须说清：**SPT 不会自动加载任意目录下的任务**。SPT 的 `CustomQuestService` 是给
mod 在内存里调的 API，不扫任何目录 —— 真正读文件的是各家 mod 自己的加载器。所以任务要生效，
得存到一个**会去读它**的 mod 下面：

- 装了 VisitAPI 服务端 mod → 它会读自己目录下的 `db\quests`，存这儿就行
- 或者存进别的用同一套约定的 mod
- 或者先存着，之后自己写个加载器

编辑器启动时会扫 `SPT_Runtime\user\mods\*\db`，把候选列出来让你挑；也可以自己填一个路径
（目录不存在会连 `quests` / `locales` 一起建出来）。选过一次就记住。

**关于自定义商人**：别的 mod 注册的商人（`db\traders\<id>\base.json`）会自动出现在商人列表里。
如果那个商人 mod 还没装、或还没适配当前 SPT 版本，编辑器会提示「这台机器上没找到」——
这时点一下「这个商人我认识」就不再提醒，不影响你继续写。

**关于任务配图**：SPT 只会伺服 `SPT_Data\images` 下的图，**模组自己目录里的图它不会自动去读**。
想让你自己的图在游戏里显示，得由那个模组注册一下：

```csharp
imageRouter.AddRoute("/files/quest/icon/" + 不带扩展名的文件名, 图片的绝对路径);
```

VisitAPI 服务端会把自己 `images\quest\icon\` 下的图全部注册好；换成别的模组就得自己加这一行——
选择器的「自己填路径」那一页写着这件事。另外路由键**不带扩展名**（SPT 两边都截到第一个点），
所以文件名里多一个点就永远匹配不上，选择器会把这种名字标出来。

### 回写保真

编辑器保存时**不会重排你的文件**：

- 文件头按原顺序重放，**注释原文照抄**
- 节点体里的注释挂在它后面那个元素上，一个字不丢
- 触发器行**原文保留**（坐标是 `float`，重新格式化会把手填的 `0.09` 印成 `0.090000003576`）
- 任务别名反查回原名，不会把 `quest sora = 5043…` 下面全变成裸 ID
- 解析不了的行降级成原文保留，绝不假装能重新生成

实测：一份 179 行的真实剧本，打开→立刻保存，**177 行逐字节一致**，
唯二两处是原文件行尾多打的空格被去掉了。

**`.dlg` 的文本只有一个地方生成**：C# 的 `DialogWriter`。前端只把模型发给本地服务端，
从不自己拼字符串 —— 两套写实现迟早会不一致，而不一致的代价是别人的剧本。
（界面上「查看 .dlg」看到的，就是按保存会写进文件的那份文本。）

任务 json 同理：**只改我们认识的字段，其余原样搬运**。不做强类型模型，
就是为了不把 SPT 里那些我们没建模的字段（`arenaLocations` / `gameModes` / …）静默丢掉。

覆盖前都会自动留一份 `.bak`。

### 安全

这是一个能读写你硬盘的本地服务，所以：

- **只绑 `127.0.0.1`**，绝不绑 `0.0.0.0`
- 端口每次启动**动态分配**
- 每次启动生成**随机令牌**注入页面，所有接口都要验；别的网页跨域读不到我们的页面，就拿不到令牌
- 所有路径**必须落在工作区内**，`..` 穿越一律拒绝
- 只服务白名单内的媒体类型

### 从源码构建

```powershell
git clone <this-repo>
cd "VisitAPI Editor"
.\build.ps1              # 产出 dist\VisitAPI.Editor.exe
```

或者手动：

```powershell
dotnet publish src\VisitAPI.Server\VisitAPI.Server.csproj -c Release
```

需要 [.NET 10 SDK](https://dotnet.microsoft.com/download)。产出是**单文件、不自带运行时**的 exe。

### 项目结构

```
src/
├─ VisitAPI.Dlg/      .dlg 解析与回写（netstandard2.0）—— 插件也用这份源码
├─ VisitAPI.Quests/   任务 / 文案 / 校验 / 只读 SPT_Data / 任务↔对话的挂接
└─ VisitAPI.Server/   自托管服务端 + 界面（index.html + quest.css/js，整包嵌进 exe）
```

**`VisitAPI.Dlg` 是和插件共用的**。插件（net472，跑在 Unity 的 Mono 里）通过 csproj 的
`<Compile Include="...">` 直接链这份源码，而不是引用 DLL——这样插件保持单文件发布，
且两边永远不可能出现"编辑器预览正常、进游戏不对"的解析分歧。

更细的内容见 [docs/ARCHITECTURE.zh-CN.md](docs/ARCHITECTURE.zh-CN.md)。
